Three actors, one workspace

The framework lives in .governance/. Humans own decisions. Agents draft and execute. The framework enforces the contract.

Human

Writes/accepts specs and plans, confirms findings, opens PRs, owns merges.

AI agent

Challenges first, drafts plans, generates code/tests, surfaces suspected findings, records progress.

Framework

Schemas, CLI, MCP (sdd serve), CI gates — the shared source of truth.

Stage 01

Bootstrap the repo

Install the tool and scaffold governance so every later stage has a place to land.

Human Framework
  1. Install the CLI (and MCP extras if you use Cursor / Claude).
  2. Run init in the target repository.
  3. Check adoption with doctor — fix missing milestones early.
  4. Wire MCP so agents call tools instead of grepping blindly.
pip install 'sdd-plus-plus[full]'
cd your-repo
sdd init
sdd doctor
sdd serve   # MCP for the IDE

Tip. Day-one success is a green doctor score trajectory and a real owner handle in the first capability — not a perfect architecture.

Stage 02

Define capabilities & contracts

Executable specs beat prompt snippets. Each feature area gets a capability with invariants, forbidden behaviors, and named acceptance cases.

Human owns AI may draft
  1. Register the capability in REGISTRY.yaml.
  2. Author capabilities/<id>/spec.yaml — purpose, contract, cases, forbidden.
  3. Keep principles and coding standards human-owned; agents load them each session.
  4. Validate before treating the spec as real.
sdd validate
# Agents (MCP):
#   get_principles()
#   get_capability(id)
#   get_coding_standards()
Do not let the agent unsupervised-commit principles, arch_spec, or capability specs. Drafts are fine; humans verify ownership.

Stage 03

Task → plan → human accept

Work starts from a task (Git issue or task card). The agent drafts a plan with a real challenge block. Only a human accepts.

Human AI drafts Acceptance gate
  1. File the task (issue / task card) with a clear goal.
  2. Ask the agent to draft a plan for that task.
  3. Agent loads capability + findings + standards, then challenges (concerns + alternatives).
  4. Plan saved as status: draft.
  5. Human accepts after review — or rejects with notes.
# Agent proposes draft
sdd plan new --task DOCS-1 --capability <id>

# Human only
sdd plan accept --id <plan-id> --by @you

# Agents (MCP):
#   propose_plan(...)
#   list_findings(capability=...)
Do not ask the agent to accept its own plan. If asked, it must refuse.

Stage 04

Implement against the plan

Code and tests follow the accepted plan and named case_ids. Smallest diff that satisfies the contract.

AI implements Human reviews Spec binds
  1. Agent reads plan scope, non_goals, and do_not_modify.
  2. Search existing patterns before generating new ones.
  3. Write tests for named case_ids — assert the contract, not the implementation.
  4. Run the named contract tests locally; failures mean the code is wrong.
pytest tests/contract/ -k <case_id>
sdd validate

Bound authority. Anything in non_goals, forbidden, or do_not_modify is a hard stop — redesign or escalate.

Stage 05

Capture findings & tech debt

Gotchas, vulnerabilities, and rough code become findings — not chat lore. Tech debt uses the same store with triage tags.

AI suggests Human confirms
  1. During work, agent files status: suspected findings.
  2. Tag debt: tech-debt, vulnerability, or code-smell.
  3. Human confirms, mitigates, or refutes.
  4. Future sessions load findings before generating related code.
sdd findings add --from-task DEBT-1 --title "…"
sdd findings list --tag tech-debt
make debt
make debt-open

# MCP: propose_finding / list_findings / search_findings

Convention. See .governance/wiki/debt-backlog.md — do not invent a second backlog.

Stage 06

Validate, CI, and PR ownership

Evidence before merge. Schemas, cross-refs, and human ownership disclosure gate the change.

CI gate Human owns PR Framework
  1. Run sdd validate locally before claiming done.
  2. Confirm acceptance cases for touched case_ids pass.
  3. Open a PR with task + plan IDs and ownership disclosure.
  4. CI governance workflow re-checks the contract.
sdd validate
sdd doctor
# Then open PR — link task + accepted plan
Do not weaken contract tests or skip schema failures to “make green.” Fix the artifact.

Stage 07

Progress & session handoff

Compaction beats endless context. Record what happened so the next session (human or agent) starts clean.

AI summarizes Human edits progress.md
  1. After milestones, append progress events.
  2. At session end, write a tight summary (what landed, what’s left).
  3. Next session loads get_progress() instead of replaying the whole chat.
  4. Park follow-ups in Pending actions / roadmap — not only in chat.
sdd update-status --kind milestone --message "…"
sdd update-status --kind session-end --message "…"
sdd progress refresh

# MCP: record_progress / record_session_end / get_progress
